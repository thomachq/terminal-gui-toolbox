# 发布链说明

> 适用：Terminal GUI Toolbox 的每一次正式发版。
> 仓库：`L:\AI-Workspace\terminal-gui-toolbox\gh\terminal-gui-toolbox`
> 共享目录：`\\192.168.3.12\Public\软件\AI生成的应用\terminal-gui-toolbox\`
> 本机安装：`D:\Tools\Terminal-GUI-Toolbox`

**一句话**：功能提交 ≠ 交付。这个项目的交付口径是「**构建 → 四包 → 提交 → tag →
四端推送 → 共享目录 → 本机安装 → 落盘待办**」八件事，缺一件用户就白等。

---

## 0. 前置检查

| 项 | 怎么确认 |
|---|---|
| 版本号 | `app.py` 里的 `APP_VER` **是唯一来源**，`_pack_release.py` / `_deploy_share.py` 都从这里读，不要手抄第二处 |
| 依赖 | `pip install -r requirements.txt`（`paramiko` + `cryptography`）。换过 Python 版本后这两个经常丢，缺了连测试脚本都 import 不了 |
| 打包工具 | `python -m PyInstaller --version`（本轮实测 6.22.3 / Python 3.14.7） |
| bin 组件 | `bin/` 下要有 `adb.exe` / `AdbWin*.dll` / `hdc.exe` / `libusb_shared.dll`，缺就 `python _fetch_bins.py` 从本机 SDK 补齐 |

> `bin/` 里的二进制**不进仓库**（`.gitignore` 排除），但工具包 / portable 包 /
> 本机安装都必须带上，否则「内置 bin」这条路径是空的。

## 1. 回归闸门（全绿才继续）

```bash
cd /l/AI-Workspace/terminal-gui-toolbox/gh/terminal-gui-toolbox
for f in _tsmoke _fsmoke _termapp _savetest _newconntest _vertest; do
  echo "## $f"; PYTHONIOENCODING=utf-8 python $f.py 2>&1 | tail -3
done
```

常用基线（2026-11-04 / v1.0.35）：`_tsmoke` 72、`_fsmoke` 54、`_termapp` 37、
`_savetest` 12、`_newconntest` 103、`_vertest` 32。

> **必须带 `PYTHONIOENCODING=utf-8`**：中文 Windows 控制台是 GBK，测试里会打印
> `▸` 之类的字符，直接跑会 `UnicodeEncodeError` 把整轮打断（`_termapp` 已经
> 自己加了 `errors="replace"`，其余脚本还没加）。

## 2. 构建 exe

```bash
# 旧 build 先改名，别让 --clean 去删（安全删除守卫会拦）
[ -d build ] && mv build "build.prev-$(date +%H%M%S)"

CODEBUDDY_SAFE_DELETE_ENABLED=0 python -m PyInstaller \
    --noconfirm --clean --distpath . toolbox.spec

ls -l TerminalToolbox.exe
./TerminalToolbox.exe --version      # 必须打成当期版本号
./TerminalToolbox.exe --smoke        # rc=0
```

- 历史耗时 15 秒左右；超过 2 分钟基本是依赖缺失或杀软在扫。
- exe 正常体积 **22 MB 上下**（v1.0.35 = 22,153,270 字节）。突然少几 MB 通常是
  某个模块没被打进去，先跑 `--check-tools` 看能不能找到 bin。

## 3. 打前三个包

```bash
python _pack_release.py --only kb,kit,portable
```

产物在 `_release/v<版本>/`，同时会由模板 `docs/模板-项目交接说明.md` 渲染出
**一份**交付文档（deb 构建说明自 v1.0.35 起是通用版，不参与渲染，见下）。
脚本自带 audit，末尾必须看到三行 `[ok] … 无垃圾 / 机密残留`。

**`github` 包故意留到第 7 步**：它是 `git clone` 快照，必须等四端都推完再打，
否则包里还是上一版的 `main`。

## 4. 提交

```bash
git add -A
git status --short          # 确认没有 data/、_release/、*.exe 混进来
git commit -m "v<版本>: <一句话>"
git log -1 --show-signature # 必须是 GPG Good signature
```

仓库开了 `commit.gpgsign=true`，GPG 不通会直接提交失败 —— 不要用
`--no-gpg-sign` 绕过，四端验签就断了。

---

## 5. 打 tag

```bash
git tag -s v<版本> -m "v<版本>: <一句话>"
git tag -v v<版本>          # 看得到 tagger / Good signature
```

## 6. 推四端

令牌在 `L:\AI-Workspace\仓库同步令牌.txt`（`gitcode：` / `gitee仓库同步令牌：` /
`github仓库同步令牌：` / `forgejo仓库同步令牌：`，分隔符是**全角冒号**）。

```bash
F=/l/AI-Workspace/仓库同步令牌.txt
tok(){ grep "^$1" "$F" | sed 's/^[^：]*：//' | tr -d '\r\n'; }
V=<版本>

GIT_TERMINAL_PROMPT=0 git push "https://x-access-token:$(tok github)@github.com/thomachq/terminal-gui-toolbox.git" main v$V
GIT_TERMINAL_PROMPT=0 git push "https://thomachq:$(tok gitee)@gitee.com/thomachq/terminal-gui-toolbox.git" main v$V
GIT_TERMINAL_PROMPT=0 git push "https://thomachq:$(tok gitcode)@gitcode.com/thomachq/terminal-gui-toolbox.git" main v$V
GIT_TERMINAL_PROMPT=0 git push "https://thomachq:$(tok forgejo)@chromas.synology.me:32443/thomachq/terminal-gui-toolbox.git" main v$V
```

四条都要看到 `main -> main` **和** `* [new tag]`。命令输出里有令牌，**别把
原始输出贴到聊天/文档里**（历史命令都接了 `sed 's#https://[^ ]*@#https://***@#g'`）。

重打过的 tag 要加 `--force`：

```bash
git push --force <url> refs/tags/v$V
```

## 7. 补 github 源码包

```bash
GIT_CONFIG_COUNT=1 \
GIT_CONFIG_KEY_0="url.file:///L:/AI-Workspace/terminal-gui-toolbox/gh/terminal-gui-toolbox/.insteadOf" \
GIT_CONFIG_VALUE_0="git@github.com:thomachq/terminal-gui-toolbox.git" \
python _pack_release.py --only github
```

为什么要这串 `insteadOf`：打包脚本的 `GH_URL` 是 `git@github.com:...`，而**本机
SSH 到 GitHub 不通**（clone 300 秒超时 / `early EOF`）。用 `insteadOf` 把 SSH
地址映射到本地仓库，clone 秒成，**而且包内 `.git/config` 里仍是干净的 SSH
地址**（把带令牌的 HTTPS URL 写进 origin 会被一起打进 zip，等于泄密）。

产物：`_release/v<版本>/terminal-gui-toolbox-<版本>(github).zip`

## 8. 共享目录

```bash
python _deploy_share.py <版本>
```

末尾必须是 `全部就位（大小逐个核对过）`；出现 `缺 …` 说明第 3/7 步没打全，
**不要继续装本机**，先把包补齐。

这个 SMB 共享**不允许删除、也不允许覆盖已存在的文件**，脚本的归档策略是
`name` → `name.prev` → `name.r2` → `name.r3` …（撞名顺延）。所以共享目录里会
看到 `.prev` / `.r2` / `.r3` 这类留档，属于正常现象。

## 9. 本机安装

```bash
python _deploy_tools.py
```

覆盖 `D:\Tools\Terminal-GUI-Toolbox` 的 `TerminalToolbox.exe`、`使用说明.txt`
和整个 `bin/`（**只等不杀**：exe 被用户开着的实例占用时，每 5 秒重试、最多
15 分钟）。

用户正在用程序时不要用 `taskkill` —— 那个实例就是用户自己开的，杀了等于把人
正在跑的会话掐掉。等不到就如实报出来，让用户关掉再跑一次。

验收：

```bash
cd /d/Tools/Terminal-GUI-Toolbox
./TerminalToolbox.exe --version     # 当期版本
./TerminalToolbox.exe --check-tools # 应用目录 / 内置 bin / ADB / HDC 都对
```

## 已知的坑（都是真踩过的）

| 现象 | 原因 / 处理 |
|---|---|
| `git push` 到 GitHub 卡死无输出 | hosts 把 `github.com` 指到 `127.0.0.1:443`（本机加速器）。**重试一次基本就过**；`--progress` 能让过程有输出，不至于被当成挂死 |
| `git@github.com` clone 超时 / `early EOF` | 本机 SSH 到 GitHub 不通。用第 7 步的 `insteadOf` 走本地仓库 |
| `fetch --tags` 报 `would clobber existing tag` | 重打过 tag。脚本已加 `--force`；手工操作时也要加 |
| github 包**静默不生成** | 上面的 fetch 失败会让整个复用分支放弃。看 `[warn] 复用已有克隆失败` 就知道，别以为打好了 |
| `UnicodeDecodeError: 'gbk' codec can't decode` | 子进程输出是 UTF-8（如 `git log` 的中文提交信息），父进程按 GBK 解。子进程调用要显式 `encoding="utf-8", errors="replace"` |
| 中文断言全 FAIL | 同上反过来：被测程序输出 GBK，测试按 UTF-8 解。`_vertest` 已改成先 utf-8 再 gbk |
| `WinError 5 拒绝访问` 保存失败 | 目标文件被杀软/并发读打开。全项目已统一走 `core/atomicio.py`（重试 5 次 → 覆写兜底），新写文件不要再用裸 `os.replace` |
| 共享盘上删文件失败 | SMB 没有回收站，IDE 的「安全删除」会拒绝。归档用改名（脚本已处理），真要删得在资源管理器里手动删 |
| 切到 COM 卡 8 秒 | 用了 `port_labels()`（PowerShell 查 WMI，8 秒超时）。下拉只用 `list_ports()`（读注册表，0 秒） |

## 回滚

- **只回滚本机**：`_release/` 里保留着历史产物，拿上一版 portable 解压覆盖
  `D:\Tools\Terminal-GUI-Toolbox` 即可（`data/` 是用户数据，不要动）。
- **回滚远端**：`git revert <提交>` 后重新走一遍发布链，**不要** force push
  `main`。
- **撤销 tag**：本地 `git tag -d v<版本>`，远端 `git push --delete <url> v<版本>`，
  然后按正确提交重打。四端都要删。
