> 适用：Terminal GUI Toolbox 的每一次正式发版。

**一句话**：功能提交 ≠ 交付。这个项目的交付口径是「**清单闸门 → 构建 → 四包 → 提交 →
tag → 四端推送 → 共享目录 → 百度网盘 → 本机安装 → 落盘待办**」十件事，缺一件用户就白等。

在此之前网盘同步一直靠人记得（结果连漏三版，见 H-REL-1）。

## 2. 构建 exe

```bash

[ -d build ] && mv build "build.prev-$(date +%H%M%S)"
```

  某个模块没被打进去，先跑 `--check-tools` 看能不能找到 bin。

重打过的 tag 要加 `--force`：


## 7. 补 github 源码包

```bash
GIT_CONFIG_COUNT=1 \
GIT_CONFIG_KEY_0="url.file:///L:/AI-Workspace/terminal-gui-toolbox/gh/terminal-gui-toolbox/.insteadOf" \
GIT_CONFIG_VALUE_0="git@github.com:thomachq/terminal-gui-toolbox.git" \
python _pack_release.py --only github
```

为什么要这串 `insteadOf`：打包脚本的 `GH_URL` 是 `git@github.com:...`，而**本机
SSH 到 GitHub 不通**（clone 300 秒超时 / `early EOF`）。用 `insteadOf` 把 SSH
地址映射到本地仓库，clone 秒成，**而且包内 `.git/config` 里仍是干净的 SSH
地址**（把带令牌的 HTTPS URL 写进 origin 会被一起打进 zip，等于泄密）。

产物：`_release/v<版本>/terminal-gui-toolbox-<版本>(github).zip`

## 8. 共享目录

```bash
python _deploy_share.py <版本>
```

末尾必须是 `全部就位（大小逐个核对过）`；出现 `缺 …` 说明第 3/7 步没打全，
**不要继续装本机**，先把包补齐。

这个 SMB 共享**不允许删除、也不允许覆盖已存在的文件**，脚本的归档策略是
`name` → `name.prev` → `name.r2` → `name.r3` …（撞名顺延）。所以共享目录里会
看到 `.prev` / `.r2` / `.r3` 这类留档，属于正常现象。

## 10. 落盘待办

三件事，缺一件都不算落盘：

1. 改 `_TODO_<日期>.md`：写清这一版改了什么、发布结果表、踩到的坑（批次视图，
   在 `任务清单.md` 的批次索引里补一行指向它）。
2. 改 `需求及问题处理清单.md`：本版对应条目的状态、处理时间线、证据、折扣与缺口。
3. 改 `未完成待办.md`：本版关掉哪条、新开哪条、还欠什么。

然后 `python _issueboard.py`（重生成看板）→ `--check` → 提交推四端。
**这一步不是可选项** —— 会话一压缩，没落盘的东西等于没发生。

## 11. 需求与问题清单闸门（2026-11-22 起，与回归闸门同权重）

**为什么有这一节**：用户多次指出「没有按照我的要求处理，或者处理上打折扣」，
而本项目当时只有按版本记的 `_TODO_<日期>.md` —— 它记「这一版改了什么」，
**不记「用户要什么、实际做到什么」**。于是折扣可以无声消失。

三份文件（都在仓库根，随 git 走四端）：

| 文件 | 视角 | 记什么 |
|---|---|---|
| `需求及问题处理清单.md` | 问责 | 每条需求的提出时间（秒级）、用户原话、验收判据、状态、证据、**折扣与缺口** |
| `任务清单.md` | 批次 | 这一轮干了哪些活、对应哪份 `_TODO_*.md` |
| `未完成待办.md` | 欠账 | 只列还没做的，含阻塞原因与解除条件 |

发版前后各过一遍：

```bash
python _issueboard.py           # 重生成看板（改过正文就必须跑）
python _issueboard.py --check   # 过期则退出码 1，不许带着旧看板发版
```

闸门判据（逐条打勾才允许第 2 步）：

1. 所有 `正在进行` 的条目 → 收口，或显式转 `挂起`/`无法完成` 并写明原因；
2. 所有 `已完成` 的证据 → 落笔后原地复跑一遍（命令 / 查询 / 截图对得上）；
3. 看板「带缺口的已完成」里的每一条，都能在总表里找到承接它的新条目；
4. 子项单独过一遍（父条目已完成但子项没做，是最容易漏的一类）；
5. 收尾留一行核验记录：`<时间> 回清单核验：覆盖 R-00x~R-0yy + H-xxx，结论=…`。

> 状态只有六个值：`已完成` / `未开始` / `正在进行` / `挂起` / `无法完成` / `作废`。
> **「部分完成」不是状态** —— 它是 `正在进行` 加上写清的折扣，设这个状态等于给打折发通行证。

## 12. 百度网盘同步（2026-11-22 起，正式列为发布链一步）

**位置**：本机 CloudDrive2 实例（`127.0.0.1:29798`，读写令牌作用域 `/百度网盘`），
路径 `/软件/AI生成的应用/terminal-gui-toolbox`（即网盘上的 `/百度网盘/软件/AI生成的应用/terminal-gui-toolbox`）。
结构必须与 NAS 同构：根目录最新版 + `历史版本/`。

```bash
SK="$HOME/.codebuddy/skills/clouddrive2"
node "$SK/bin/cd2.js" ls "/软件/AI生成的应用/terminal-gui-toolbox" --refresh
node "$SK/bin/cd2.js" upload "<本地文件>" "/软件/AI生成的应用/terminal-gui-toolbox" --name "<云端文件名>"
node "$SK/bin/cd2.js" hash "/软件/AI生成的应用/terminal-gui-toolbox/<文件名>"
```

要点：

- **固定名产物（工具包 / 知识库 / 交接说明 / deb 说明 / 三份清单 / 本文）先 `rename` 加版本标签
  再 `mv` 进 `历史版本/`**，然后传新件 —— 直接覆盖会留下 `xxx(2).zip` 这种没法读的名字。
- **一致性判据只能是「size + 直链下载后本地算 md5」**。云端 `md5` 字段是百度自有算法：
  2026-11-22 实测网盘 `发布链说明.md` 云端 md5 `98f1b5b0…`、下载回来算 `960c4810…`，
  size 都是 10265。**拿云端 md5 比对会误判**（本机版 CD2 的 `verify` 也会报 DIFF）。
- 大文件不硬算 md5：size 相同 + 版本号相同就视为同一份（验证成本高于操作成本）。
- `ls` 默认读缓存，刚传完要 `--refresh` 才能看到；中文文件名管道给 python 必须
  `PYTHONIOENCODING=utf-8`。

## 已知的坑（都是真踩过的）

| 现象 | 原因 / 处理 |
|---|---|
| `git push` 到 GitHub 卡死无输出 | hosts 把 `github.com` 指到 `127.0.0.1:443`（本机加速器）。**重试一次基本就过**；`--progress` 能让过程有输出，不至于被当成挂死 |
| `git@github.com` clone 超时 / `early EOF` | 本机 SSH 到 GitHub 不通。用第 7 步的 `insteadOf` 走本地仓库 |
| `fetch --tags` 报 `would clobber existing tag` | 重打过 tag。脚本已加 `--force`；手工操作时也要加 |
| github 包**静默不生成** | 上面的 fetch 失败会让整个复用分支放弃。看 `[warn] 复用已有克隆失败` 就知道，别以为打好了 |
| `UnicodeDecodeError: 'gbk' codec can't decode` | 子进程输出是 UTF-8（如 `git log` 的中文提交信息），父进程按 GBK 解。子进程调用要显式 `encoding="utf-8", errors="replace"` |
| 中文断言全 FAIL | 同上反过来：被测程序输出 GBK，测试按 UTF-8 解。`_vertest` 已改成先 utf-8 再 gbk |
| `WinError 5 拒绝访问` 保存失败 | 目标文件被杀软/并发读打开。全项目已统一走 `core/atomicio.py`（重试 5 次 → 覆写兜底），新写文件不要再用裸 `os.replace` |
| 共享盘上删文件失败 | SMB 没有回收站，IDE 的「安全删除」会拒绝。归档用改名（脚本已处理），真要删得在资源管理器里手动删 |
| 切到 COM 卡 8 秒 | 用了 `port_labels()`（PowerShell 查 WMI，8 秒超时）。下拉只用 `list_ports()`（读注册表，0 秒） |
| 网盘「md5 不一致」但其实同一份 | 云端 md5 是百度自有算法，不是文件 md5。判据用「size + 直链下载后本地算 md5」，别信云端字段 |
| 同大小不同内容被「跳过覆盖」 | `_deploy_share.py` 与网盘同步都只看 size。同版本重打包且大小恰好相同就会漏更新；确知重打过要手工覆盖（`--verify-hash` 开关待做，见 R-008） |
| 网盘漏同步好几版 | v1.0.33~1.0.35 就是这样，因为网盘不在发布链里。2026-11-22 起列为 §12，必做 |
| 看板与正文打架 | 改了 `需求及问题处理清单.md` 正文却没跑 `_issueboard.py`。发版闸门会 `--check` 拦下 |

## 回滚

- **只回滚本机**：`_release/` 里保留着历史产物，拿上一版 portable 解压覆盖
  `D:\Tools\Terminal-GUI-Toolbox` 即可（`data/` 是用户数据，不要动）。
- **回滚远端**：`git revert <提交>` 后重新走一遍发布链，**不要** force push
  `main`。
- **撤销 tag**：本地 `git tag -d v<版本>`，远端 `git push --delete <url> v<版本>`，
  然后按正确提交重打。四端都要删。
