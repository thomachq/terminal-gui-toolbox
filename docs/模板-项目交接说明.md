## 1. 这是什么

一个 Windows 上的多协议终端工具箱：连 SSH / Telnet / 本机，连上后自动探系统，
把常用运维动作（网络工具、系统信息、文件管理、防火墙、路由、Docker、Web 服务、数据库、
计划任务、安全扫描、证书管理）做成页面，另外带一个**智能运维助手**。

三条硬约束贯穿整个项目，改代码前必须先看懂：

1. **零安装**：不往被管机器上落任何 agent、脚本、守护进程。全部能力只用对方已有的
   SSH/Telnet + 系统自带命令与配置文件实现。判断标准是「断网还能不能用」——
   联网调模型 API 是允许的。**这条优先级最高，任何新功能都不能为它让步。**
2. **凭据只在本地加密**：口令、私钥、Key 一律进 `data/*.dat`（cryptography AES-GCM），
   界面永不回显原文，只显示「已设置 · N 位」。
3. **单实例**：一个进程开着，第二次启动只会把已有窗口叫到前台，然后自己退出（详见 §5）。

## 3. 启动与打包

```bat

:: 统一用 python -m 或直接跑脚本名，例如：

_tooltest  _kvfit  _navsb  _navaudit  _pagerolltest  _keytest  _synoreadtest  _termdock  _shotfiles


:: 注意：_tsmoke 的「sec · tbl_fw」一项在 reg.exe / schtasks.exe 被安全策略
:: 拦掉的环境里必然红（切到「防火墙」页签会触发探测，探测要读注册表），
:: 那不是回归；其余项与环境无关。

:: 交付四包（前三个会用到 exe；github 那个必须在推完四端之后单独打）
:: 两份 Markdown 文档会由 render_docs() 从 docs/模板-*.md 自动生成，不用手工放

:: 推到共享目录（SMB 只允许新建/改名，见 §5；缺文件会直接报错拒绝部署）
```

打包注意：`toolbox.spec` 的 `hiddenimports` 必须补齐 `core.*` / `pages.*` / `ui.*`
（这些是运行时 import，静态分析会漏）。漏了的表现是 exe 启动即崩或缺页。

`_pack_release.py` 打完会跑 `audit()`，逐个包复查垃圾文件与 `data/` 机密目录，
命中就返回非零 —— **看到 `[error] ... 别分发` 就别往下走**。

## 5. 已知取舍与坑（接手必读）

**产品层面的规矩**

- **不要再往远端装东西**：所有功能必须能用纯命令实现，做不到就降级为「连上才采」。
- **布局别自作主张**：页签位置、面板层级由用户定。改前先问。
- **三种视图的规矩**：终端与设置都能「页签 ↔ 独立窗口」；**智能运维助手永远只做侧边栏**，
  绝不进页签（它和终端要并排看，做成页签互相挡）。
- **终端与助手的容器层级**：`paned` 必须挂在窗口层（`app._body`），挂在页面里会导致
  终端一占满整页就把助手侧栏盖住。
- **模型配置双写**：`ai.json` 的扁平字段永远是「当前模型」的镜像；切模型 = 把档案写回
  扁平字段，引擎不用改。只有扁平字段的老 `ai.json` 会静默升级成一条「默认模型」。
- **最后一条模型删不掉**：删空助手就没模型可用。

**数据层**

- **「是不是自己」必须按主键判，不能按对象身份判**：主机档案以名字为主键、没有 id，
  而 `validate()` 收到的是表单合并出来的**新 dict**，`o is rec` 永远不成立 ——
  编辑任何一台主机都会被判「名称已被占用」，用户看到的是「改一下就存不了」。
  现在 `H.validate(rec, others, skip_name=旧名字)`。凭证 / 代理 / 脚本三页有 id，
  一律用 `skip_id`，别改回去。
- **改名 = 删旧 + 增新**：主机名是 `profiles.dat` 的主键，不先 `remove(old)` 就会留下孤儿。

**交付链**

- **交付文档必须是模板，不能只活在 `_release/` 里**：`交接说明` 与 `deb构建说明`
  早期是手工放进 `_release/<版本>/` 的，忘了放就等于没交付 —— `add_file()` 静默返回
  False、`_deploy_share.py` 静默打印「跳过（本地没有）」，共享盘上那两份从 v1.0.6
  一直卡到 v1.0.12 才被发现（**整整 7 个版本**）。现在真身在 `docs/模板-*.md`，
  `_pack_release.render_docs()` 每次打包把版本号与日期代入模板生成，
  渲染完还会扫一遍有没有漏替换的占位符（有就直接抛错）；
  `_deploy_share.py` 动手前预检六个文件，缺一个就整轮拒绝部署。
- **发版顺序不能调**：改代码 → 跑测试 → 改 `APP_VER` 与 `_pack_release.VER` →
  PyInstaller 打 exe → 跑 `_texe` → 打 kb/kit/portable → 提交 + 签名 tag + 推四端 →
  `--only=github` 补快照 → `_deploy_share.py` → 覆盖 `D:\Tools`。
  **github 快照必须在推完之后打**，否则包里 main 还是上一版。
- **不建 Release、不挂二进制**：只打签名 tag。要 exe / deb 的人自己从源码构建。

**提权**

- **「提权验证过」不等于「终端带权限」**：这是 v1.0.14 之前的真实故障 ——
  界面勾了「连接后自动提权」，状态栏还写着「sudo -i 已生效，之后的命令都带
  root 权限」，用户在终端里敲 `id` 看到的还是自己。两个原因叠在一起：
  ① `sudo_ok()` 只做 `sudo -v` 验一次密码，**没有真的进 root**；
  ② 终端固定调 `run_traced()`，那是不带任何提权的通道 —— 只有页面上显式调
  `run_admin()` 的按钮才带 sudo。
  现在 `SSHSession.elevate_root()` **真的进去**：类 Unix 开一条 `invoke_shell`
  持久 shell 执行 `sudo -i`（交换机走 `enable`），并把 shell 存进 `_root_shell`；
  终端命令交给 `core.session.term_exec()` 分派 —— 有 root shell 就发过去，
  没有但 `elevated` 已真就走 `run_admin()`，都没有才 `run_traced()`。
- **`sudo -i` 必须走持久 shell，不能用 exec 通道**：`exec_command` 每条都是新
  会话，`sudo -i` 进去就退出来了，状态带不过去。判定「进没进去」也不能只看
  提示符（有的发行版 root 也用 `$`），`CLIClient.sudo_i()` 进完跑一次
  `id -u`，输出是 0 才算数。
- **别把 `is_root` 当「已提权」用**：`is_root` 表示「登录用户本身就是 root」。
  `sudo -i` 之后 exec 通道还是原用户，所以 `elevate_root()` 刻意**不碰**
  `is_root`，否则 `run_admin()` 会误以为不用 sudo，把页面上的写操作全弄坏。
  **但反过来也有坑**：终端提示符当初就是按 `is_root` 画的，于是提权成功了
  提示符还顶着 `$` —— 用户一眼就断定「没提权成功」。v1.0.17 起提示符按
  `is_root or elevated` 判，提权后显示 `root@host …#`。**用户判断提权成没成，
  看的就是这一行**，它必须说实话。
- **口令提示的正则要吃下「for 用户名」**（v1.0.17 的真正根因）：sudo 默认打印
  `[sudo] password for cloudadmin: `，而原来的 `_PASSWORD` 要求 `password`
  紧跟冒号 —— 于是**密码永远发不出去**。表现极具误导性：sudo 在等密码、我们在
  等回显，超时后程序把下一条 `id -u` 当密码喂进去，sudo 回一句
  `Sorry, try again`，最终只落一个「提权未生效」。现在是
  `(?:password|passwd)\s*(?:for\s+[^\s:：]+)?\s*[:：]`。
  → 教训：**「没人报错」不等于「做对了」**。凡是「发出去等回包」的握手，
  都要断言「该发的确实发了」（`_elevtest` 第 7 段现在会检查 `secret` 在
  `sent` 里），否则一路 False 也能"顺利"跑完。
- **「提权函数返回 True」也要再落一锤**：`elevate_root()` 只代表提权那一步的
  回显看着对；终端真正执行的可能是另一条通道（root shell / `run_admin`）。
  连接流程现在会调 `verify_root()` **实测一次 `id -u`**，不是 0 就当失败，
  并把真实 uid 写进状态栏。
- **`sudo -i` 不是唯一活路**：群晖 DSM、部分加固过的发行版会把 `sudo -i` 关掉
  但放行 `sudo <cmd>`。`elevate_root()` 失败后会退回 `sudo_ok()`（逐条 sudo），
  成功则 `elev_method="percmd"`，终端命令经 `run_admin()` 逐条套 sudo ——
  结果一样是 root，只是每条多一次 sudo。
- **口令留空要兜底**：勾了自动提权但只填了登录密码时，服务器上两者通常相同，
  现在会拿登录密码去试（开关不兜底：enable 密码和登录密码是两回事，试错还会
  锁账号）。不兜底的话用户会看到「缺密码、没提权」，然后被当成「提权不生效」。

**Docker / 设备探测**

- **`command -v docker` 找不到 ≠ 没装**（v1.0.18）：群晖把 docker 装在
  `/var/packages/ContainerManager/target/usr/bin/docker`，只在 `/usr/local/bin/docker`
  留一个符号链接；而 SSH 会话的 PATH 通常只有 `/usr/bin:/bin:/usr/sbin:/sbin`。
  用户明明在 Container Manager 里跑着 15 个容器，界面一路报「未安装」。
  `DockerEngine._locate()` 现在用**一条**命令把候选绝对路径挨个试一遍
  （`for p in docker /usr/local/bin/docker …; do command -v "$p" && break; done`），
  省得为每个候选开一条 exec 通道。
- **免密 sudo 那条路必须试**（同一个 bug 的另一半）：群晖给 administrators 组配了
  `NOPASSWD`，用户根本没填 sudo 密码；旧代码只在「有密码」时才试 sudo，于是永远
  走不到能过的那条。现在顺序是 直连 → `sudo -n` → 带密码 sudo，分别记
  `sudo_mode = nopasswd / admin`，后续命令由 `_cmd()` 自动补 `sudo -n` 前缀。
  → 顺带挖出个静默坑：`can_admin()` 返回的是 `(bool, 原因)` 元组，写成
  `ok, _ = s.can_admin()` 遇到返回裸 bool 的实现会 `TypeError`，被 `except` 吞掉，
  症状和上面一模一样（「有密码却不试 sudo」）。现在两种形状都认。
- **`--format '{{json .}}'` 在群晖上要 65 秒**：`ps` 65s、`images` 43.9s、
  `system df` 82s（直接撞 60 秒超时，被判成「执行失败」）。改成字段模板
  `{{.ID}}{{"\x1f"}}{{.Names}}…` 之后 `ps`/`images` 都是 **0.1 秒** —— 同一个 daemon、
  同一批容器，差别全在「让 docker 拼一份完整 JSON」上。`_list()` 先走字段模板，
  拿不到才退回 `{{json .}}`（兼容老版本）；`parsers._records()` 两种格式都吃，
  字段数对不上的行直接丢掉，不往表格里塞半截数据。
- **`system df` 慢是 daemon 自己的事**：即便用字段模板仍要 ~50 秒（要遍历所有层）。
  它不在首屏，`df()` 有 `except DockerError: return []` 兜底 —— **别把它挪到首屏**。

**对外接口（智能体接入页）**

- **令牌必须打码，但复制要复制明文**（v1.0.18，用户要求）：界面显示
  `ttb_************`（固定 12 个星号，不泄露真实长度），行尾一个「复制」按钮把
  **真令牌**送进剪贴板。`KVGrid` 的项从 3 元组扩成
  `(label, value, tone, (按钮文字, 回调))`；注意 `set_items()` 必须原样保留第 4 项 ——
  早年它只截到 3 项，按钮会被**静默吃掉**，界面上什么也不报
  （`_tokentest.py` 20 项把这条钉住）。
- **`ssh-toolbox` 技能**（`~/.workbuddy/skills/ssh-toolbox/`）：用本机 API 连 SSH，
  `run --device 名字 "命令"` 一步到位，`--admin` 走 sudo。它自己解 `api.json` 里的
  `token_enc`（纯 Python 实现的 AES-256-GCM，零依赖，`data/.vpncert-key` 就是密钥），
  所以不需要从界面抄令牌 —— 界面上的令牌本来就是打码的。
  实测基线：群晖 `run` 1.8 秒、`--admin` 1.4 秒。
- **API 跑的命令要进日志，必须给会话挂 tracer**（v1.0.19）：会话池走的是
  `session.run()` / `run_admin()`，**这两条都不带 tracer**（只有 `run_traced()` 带），
  所以智能体在设备上跑了什么，日志里是空白。现在的做法是
  `SessionPool(..., tracer=app._trace_cmd)` + `open()` 时包一层 `_tagged()`
  给每条命令加 `[API]` 前缀（连 `detect()` 阶段的探测也算，否则日志里会冒出
  一批「不知道谁跑的」命令）；`exec()` 再显式 `_trace()` 一次。
  主程序按前缀分流：带前缀 → 事件 `ai.command`、分类「AI」、执行者「智能体」；
  不带 → `terminal.command`、执行者「用户」。**别把两类合回一条** ——
  同一个命令，人点出来的和模型跑出来的，事后处理方式不一样。
- **日志底栏的高度判据是「表格露出几行」，不是面板总高**（v1.0.19）：面板 210px 时
  表格只剩 50px —— 用户看到的是一行表头加一个分页条，直说「显示都不完整」。
  现在默认 280 逻辑像素、下限 200；**老版本存下来的 `< 240` 一律当「没设置过」**
  重新抬到默认（用户机器上存的就是 170），否则改了默认值也白改，因为
  `window.json` 会把那个太扁的数一直带下去。`_logdocktest.py` 断言的是
  「表格本体 ≥ 5 行」，这条比量总高更能反映「能不能用」。

**Tk / ttk 的陷阱**

- **`ttk::treeview` 的 `<Motion>` 是类绑定，`after_idle` 也救不干净**：bindtags 顺序是
  widget → class → toplevel → all，所以挂在控件上的 `<Motion>` 回调永远跑在 ttk 前面，
  在里面 `configure(cursor=...)` 会被 ttk 当场改回去 —— 这是「鼠标停在数据行还顶着 ↔」的
  第一层真因。v1.0.12 改用 `after_idle` 确实排到了 ttk 之后，但 idle 要等**下一轮**事件
  循环，而鼠标每秒移动几十次：每帧都是 ttk 先设 ↔、idle 才清，中间态用户看得见，所以
  「移到哪都是双箭头」。v1.0.16 的做法是**往 bindtags 里插自定义 tag**
  （`ui/table.py` 的 `CUR_TAG`），插在 `"Treeview"` 之后并 `bind_class` 挂
  `<Motion>`/`<Leave>`：守卫与 ttk 在**同一个事件**内先后执行，屏幕只渲染最终值，
  中间态不可见。要点三条：
  ① 守卫里先看 `event.state & 0x100`（左键按着正在拖列宽）就**直接 return**，不抢 ttk；
  ② 只有 `identify_region(...) == "separator"` 才留 `sb_h_double_arrow`，其余一律 `arrow`；
  ③ 还原时显式写 `"arrow"` 而不是 `""` —— `ttk::saveCursor` 会拿当前值当默认值，留空
  等于把决定权又交回给 ttk。另外 `cget("cursor")` 返回的是 cursor 对象，比较要 `str()`。
- **`winfo_ismapped()` 不能当硬门槛**：页面构建中或窗口未映射时返回 False。
  `_maybe_auto_probe` 早期就是 `if not ismapped: return`，于是永远「未检测」。
  现在未映射时 `after(400)` 重试（最多 15 次），并且每次 `_show("hosts")` 再补一次
  （`PROBE_TTL=90s` 节流）。
- **`winfo_containing` 不能用来判断 z 序**：Windows 上它走 `WindowFromPoint`，
  窗口被别的程序盖住就返回 `None`。要判断「谁在最上面」用 `app._ws_top`。
- **Text 高度自适应**：`ui/md.py` 里必须先有真实宽度再算 `displaylines`。
- **会话状态里的 list/dict 只能原地改**：`_ai_attach` / `_ai_flow_labels` /
  `_ai_files_seen` 与 `st` 里是同一个对象，写成 `self._ai_attach = []` 会脱钩。
  一律 `[:] = []` / `.clear()`。
- **`_ai_dock_reflow` 不许记宽度**：程序摆分隔条也触发它，只在 `_ai_dock_remember()` 记，
  且存逻辑像素（÷ `U.S`）。
- **`app.session` 是 property**：直接赋值会走 setter（塞给 `sessions.active` 或新建槽位），
  测试里想换掉整个池子得动 `app.sessions` 这个更底层的对象。

**Windows 特有的坑**

- **单实例不能用 PostMessage**：Tk 不暴露窗口过程，收不到自定义 Win32 消息。
  `core/singleinstance.py` 走「命名互斥量判重 + 命名事件唤醒 + `after` 轮询」：
  `CreateMutexW` 后 `GetLastError()==183` 即已有实例；用 `Local\` 不用 `Global\`
  （后者要 SeCreateGlobal 权限）；64 位下 `restype` 必须设成 `wintypes.HANDLE`，
  否则句柄被截断；`consume()` **只能 Wait 事件句柄，绝不能 Wait 互斥量** ——
  后者会把所有权抢过来，搅乱语义。测试类参数（`--smoke` / `--page` / `--no-probe`
  / `--dark` / `--version`）不受单实例限制，否则回归跑不起来。
- **快捷方式不要走 WScript.Shell / cscript**：前者被安全策略拦（COM 任意代码），
  后者在 LOLBin 名单里。`_mkshortcut.py` 用 ctypes 在自进程内调 COM 是唯一干净路子。
- **桌面路径不许假设**：本机在 `D:\Documents\Desktop`（注册表 `User Shell Folders`），
  不是 `C:\Users\<user>\Desktop`。交付脚本一律写位置无关路径。
- **共享盘只能新建和改名**：`\\192.168.3.12\Public\...` 上 `unlink` 和 `os.replace`
  都返回「拒绝访问」，所以归档命名必须顺延（`name` → `name.prev` → `name.r2` → …），
  覆盖改用「新建临时文件 + 改名」。`_deploy_share.py` 已按此实现，末尾逐个核对大小。
- **别在项目根目录跑系统查询命令**：`sc query MSSQLSERVER > query` 会留下一个 13 字节的
  `query`，`git add -A` 就把它带进仓库 —— 从 v1.0.4 一路漏到 v1.0.12。现在打包以
  `git ls-files -co --exclude-standard` 为白名单（只对 `*.exe` 开例外），这类问题不会再进包；
  但命令本身还是要重定向到临时目录。
